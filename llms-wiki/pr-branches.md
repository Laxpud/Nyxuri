# 从个人分支准备 PR

> 本页记录 fork 的 PR 分支准备流程；实际行为以 [prepare-pr.py](../tools/prepare-pr.py) 为准。

分支职责和授权边界见[个人协作规则](fork-workflow.md)。准备贡献时，脚本从
`upstream/main` 创建独立 worktree，只带入筛选后的净改动，不继承来源分支的个人提交历史。
脚本只暂存改动，不提交、不推送、不创建 GitHub PR，也不切换当前工作目录的分支。

## 排除清单

脚本读取当前工作目录版本的根目录 `.pr-exclude`，即使它尚未提交。清单为空表示
不过滤任何路径；不隐式排除清单本身、脚本或本文档。只导出来源引用中已提交的改动，
未提交修改和未跟踪文件不会被带入。

每行是一个相对仓库根目录的文件或目录路径，开头和结尾的 `/` 可省略：

```text
# 以下仅为格式示例，不会自动写入实际清单
/AGENTS.md
/ROADMAP.md
/personal-docs/
```

- 空行和以 `#` 开头的整行注释忽略，行首尾空白忽略。
- 文件路径排除该文件；目录路径排除目录内的全部文件，匹配区分大小写。
- 不支持通配符、`!` 反选、转义和 `..`；此文件不是完整的 `.gitignore` 语法。
- 上游已有的被排除文件保留目标上游版本，个人新增的被排除文件不加入 PR。
- 重命名按删除旧路径、添加新路径分别筛选；重命名个人文件时，应同时考虑两个路径。

## 使用

先自行刷新上游引用。脚本不联网，不默认认为本地 `upstream/main` 已是远程最新：

```bash
git fetch upstream
python3 tools/prepare-pr.py --dry-run
```

默认比较 `ubuntu` 与 `upstream/main`，可用 `--source` 和 `--base` 指定其他引用。
预览显示提交 ID、包含和排除的路径，不创建分支、worktree 或提交，也不检查补丁能否无冲突应用。
没有唯一共同祖先时停止，不自行猜测应使用哪段历史。

明确决定生成分支后，指定一个尚不存在的分支和仓库外的新目录：

```bash
python3 tools/prepare-pr.py --create \
  --branch codex/pr-ubuntu-support \
  --worktree ../Nyxuri-pr-ubuntu
```

脚本以目标上游提交为起点，将来源分支相对共同祖先的筛选后改动三方应用到新 worktree。
这样既能排除个人改动，也能在没有冲突时保留上游后来增加的内容。没有可导出改动时不创建任何分支。
已有分支、已有目录不会被覆盖；补丁应用失败时返回非零状态，保留新分支和 worktree 供检查。

检查暂存内容、处理冲突并完成验证后，再自行提交和推送这个 PR 分支：

```bash
git -C ../Nyxuri-pr-ubuntu status
git -C ../Nyxuri-pr-ubuntu diff --cached
```

导出的是净改动，来源提交的作者、消息和拆分方式不会自动复制。该流程按文件路径过滤，
不能去掉普通代码文件内的个人内容；最终仍须检查差异。个人文件也仍保留在原 fork 的历史中。

## 验证范围

帮助和 `--dry-run` 可在现有仓库只读检查；语法检查不需要创建分支。完整验证还需在获准的
隔离仓库执行 `--create`，核对文件排除、二进制和权限位保留、上游并行修改与冲突保留行为。
