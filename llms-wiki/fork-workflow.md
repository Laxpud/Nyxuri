# 本 fork 的个人协作规则

> 本页是 `Laxpud/Nyxuri` 的个人协作规则源，集中维护分支职责、同步和 PR 授权边界；脚本用法见 [PR 分支指南](pr-branches.md)。

上游为 `ech678/Nyxuri`。开始 Git 操作前核对当前工作目录、分支、工作区改动和远程地址，
区分本地引用缓存与实际远程状态。

## 分支职责

| 分支 / 远程 | 用途与边界 |
| --- | --- |
| `upstream` | 原作者仓库，用于获取更新和作为 PR 的目标；不向其直接推送 |
| `origin` | 用户自己的 fork，开发分支和个人文档推送到这里 |
| `main` | 同步上游 `main`，不加入 Ubuntu 适配、个人文档或本 fork 专属工具的提交；跟踪 `origin/main` |
| `ubuntu` | 日常开发分支，保存 Ubuntu 兼容改动及个人文档、工具；跟踪 `origin/ubuntu` |
| `codex/pr-*` | 从目标上游提交准备的 PR 分支，只包含本次准备贡献的改动，推送到 `origin` 后向上游 `main` 提 PR |
| `codex/backup-*` | 操作前的恢复点，不继续开发、不作为 PR 来源；未经用户要求不删除 |

## 同步与个人文件

- **同步上游**：先获取上游并检查提交关系。`main` 优先快进；上游改写历史时保留恢复点，
  说明差异再按用户授权处理。`ubuntu` 已有独立提交后，更新必须保留兼容改动、个人文件及未提交内容，
  不得为了“与 main 一致”直接重置或强制覆盖；优先合并上游更新，改写已推送历史前取得明确授权。
- **个人文件**：允许提交到 `ubuntu` 和自己的 fork；用 `.pr-exclude` 指定不贡献给上游的路径，
  不依赖 `.gitignore` 隐藏已跟踪文件。清单为空就是没有排除规则，不能声称个人内容已自动过滤；
  未经用户要求不填充清单。规则语法和排除行为以 [PR 分支指南](pr-branches.md) 为准。
- **规则维护**：本 fork 的个人约定统一修改本页，根目录 `AGENTS.md` 只保留读取指引，
  不重复维护完整规则。同步上游 `AGENTS.md` 时接纳上游项目规范，并在 `ubuntu` 中保留指引；
  发生冲突时逐项合并，不整文件覆盖。若规则含义冲突，指出文件路径和原句，按用户明确指令处理。
- **跨分支使用**：本页随 `ubuntu` 管理；不向保持上游原样的 `main` 注入个人规则。
  在不含本页的分支或独立工作区开启新对话时，需要另行向 AI 提供这些约定，不能假定它自动继承。

## PR 与授权

- **准备 PR**：先阅读 [PR 分支指南](pr-branches.md)，运行
  `python3 tools/prepare-pr.py --dry-run` 展示包含与排除的路径；不要直接将混有个人文档的 `ubuntu` 整体提 PR。
  只有用户要求生成 PR 分支时才使用 `--create`；使用独立 worktree，不改动日常开发工作区。
- **提交与发布**：生成 PR 分支只代表准备好待审阅内容，不代表允许提交、推送或创建 GitHub PR。
  按用户明确授权执行相应步骤；只暂存本轮相关文件，提交前检查暂存差异，提 PR 前检查完整分支差异。
- **汇报**：分别说明本地分支、远程分支、暂存/提交/推送状态。不能把本地同步或预览成功说成远程更新完成。

## 检查方式

调整本页后运行现有文档契约检查，确认入口和索引链接有效；在实际 Git 操作前后核对分支、
工作区及差异是否符合以上职责。文档检查通过不等于已执行或验证同步、提交与 PR 操作。
